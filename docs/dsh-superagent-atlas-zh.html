①

控制面核心：一个画面，统管多个 session

人只面对一个 Agent；系统内部把"路由"和"执行"彻底分开，并独占写权。

核心增量：把"人面对 Agent"与"系统跑 session"解耦。Router 是常驻的全局协调者、只路由不执行；Worker 是上下文隔离的执行单元、只向 Router 汇报；Engine 用单写者 + 原子认领独占写权。人看到的永远是一个统一的 Agent。
②

端到端生命周期：一条消息如何变成 N 个隔离 session 的结果

人发一句话 → Router 拆分 → 多个 Worker 并行在隔离上下文里干 → Router 汇总成一条统一流回面板。

关键落点：并行来自"拆分 + 隔离上下文"，一致性来自"Router 单写者串行化写"。人不必关心背后有几个 session、谁先谁后——只收到一条去重排序后的统一流。
③

注意力门禁：双层过滤，决定"该不该接、接了怎么干"

Layer 1 是硬门禁（策略/授权），Layer 2 是软研判（模型判断）。被订阅的线程走快路径绕过门禁，但不授新权。

设计要点：门禁是"硬"的（只认白名单/规则/授权书，挡掉一切未授权动作），研判是"软"的（模型判断相关性与接法）。默认全走 observe——只把 Decision 记下来，人看完再决定开 auto。这把"主动性"关进了可审计的笼子里，所以论文里那种"主动提 bug 修复 PR"在原型里必须书面规则 + observe 默认才可能发生。
④

事件溯源任务账本：每个任务都是一条可重放、可审计的 JSONL

任务不是状态机里的一个字段，而是一串 append-only 事件。任意时刻都能重放还原现场、追责、回滚。

为什么是事件而非状态：把"任务进展"记成一串不可变事件，而不是一个会被覆盖的字段。好处是——出事能重放（知道哪一步、谁、为什么），能审计（每条动作有 owner 与依据），能回滚（重放到某个事件之前）。这也是 dsh-super-agent 插件相对原型仓库多出来的那一层封装。
⑤

同类格局地图：2026 年的控制面 / Agent Runtime 工具

两个维度定位：纵轴"原生控制面 vs 外挂 bolt-on"，横轴"是否有单写者 / 原子认领的共识机制"。右上是这一波的正解。

格局判断：2026 年"用一个界面管一队 agent"的控制面思路正在收敛。有意思的是——dsh 的 Engine 单写者 + Assignment 原子认领，与 Mission Control 的 SQLite WAL 单写者 + 原子 UPDATE 认领，是同一模式被独立重发。说明"谁先写谁占、杜绝双写"已是控制面的基础共识，而非某家的独门秘技。
⑥

操作系统类比：把"多 agent 调度"翻译成你熟悉的内核术语

社区最买账的一帧解读——一旦套进 OS 概念，很多设计决策立刻说得通。

一句话记忆点：把 dsh 想成"为一个 Agent 团队写的内核"——Router 是中断控制器，Inline&Spill 是缓存策略，speculative 是分支预测，Watchdog 是外部控制循环。这套类比让"为什么这样设计"从玄学变成常识。
